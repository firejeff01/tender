01 總覽摘要

1.1 工具用途

TenderSearch 是一個 Windows 桌面工具，用於每日自動抓取 政府電子採購網（web.pcc.gov.tw）的招標公告， 並提供月份行事曆瀏覽、即時搜尋、關鍵字篩選、收藏與 Excel 匯出等功能， 協助業務人員快速掌握每日新標案。

1.2 部署模式

  • 單機桌面工具：每位使用者本機獨立安裝，無共享伺服器、無多人協作。
  • 每日排程：透過 Windows Task Scheduler 在指定時間（預設 17:00）自動執行抓取。
  • 無使用者帳號：不需登入、不存任何認證、不存個資。

3.3 進程隔離

桌面 app 與爬蟲是兩個獨立進程，透過 stdout 的 JSON Lines 溝通進度。 這個設計有兩個資安好處：

  • 排程與互動觸發共用同一支執行檔：Task Scheduler 與「立即更新」按鈕 都是呼叫 Tender.Crawler.exe --mode {scheduled|manual|catchup}，行為一致、易於審查。
  • Crawler 崩潰不會帶倒桌面 app：子程序非預期結束時，桌面 app 透過 ExitCode 與 stderr 判讀錯誤，並寫入 errors.log。

3.4 重要資料流

  1. 每日 17:00 Task Scheduler 觸發 Tender.Crawler.exe --mode scheduled。
  2. Crawler 取得 lock（locks\crawler.lock），避免重複執行。
  3. 對 web.pcc.gov.tw 三種招標方式各發 GET（pageSize=2000，禮貌延遲 1.5 秒）。
  4. AngleSharp 解析 HTML <table id="tpam">，套用使用者關鍵字命中、寫入 tenders.json。
  5. 產生 summary.json 與 crawl-runs.json，釋放 lock，正常結束（exit code 0）。
  6. 桌面 app 啟動時讀 summary.json 顯示行事曆；使用者點某天才會 lazy-load 該日 tenders.json。

3.5 自動更新機制

  • 桌面 app 啟動時非同步呼叫 https://api.github.com/repos/firejeff01/tender/releases/latest。
  • 解析 tag 比對本機 assembly 版本；若有新版，工具列下方顯示 banner。
  • 使用者主動點 banner 才會在預設瀏覽器開啟 release page，不會自動下載、不會自動安裝。

04 資安設計

4.1 權限模型

動作需要權限備註
安裝 MSI本機 Administrator寫入 C:\Program Files\TenderSearch\
桌面 app 執行一般使用者不要求 admin；不寫 HKLM；不存取其他使用者的設定檔
排程任務執行使用者層級（/RL LIMITED）由桌面 app 首次啟動時建立，不需 admin
爬蟲子程序承襲呼叫者身份無提權；無 UAC prompt

4.2 網路安全

  • 白名單外連：僅 web.pcc.gov.tw（TLS 1.2+）、api.github.com（TLS 1.2+）。
  • 憑證驗證：HttpClient 預設啟用 TLS 證書驗證，無自訂回呼跳過驗證。
  • Timeout：爬蟲 30 秒、更新檢查 10 秒，避免 hang。
  • 無 telemetry：不上傳任何使用資料、紀錄、追蹤識別碼。
  • 無接收連線：不開 listening socket、不需防火牆例外。

4.3 資料安全

  • 所有資料儲存於使用者 %LocalAppData%\TenderSearch\，受 NTFS 使用者層級 ACL 保護。
  • 不存任何密碼、token、API key 或個資。
  • 不寫 Windows Registry HKLM；HKCU 僅由 MSI 寫入捷徑識別 key（非敏感）。
  • 不需要也不要求網路共享（SMB／UNC）寫入。
  • JSON 寫入使用「先寫 .tmp 再 rename」原子操作，避免中斷產生殘破檔案。

4.4 反序列化與輸入驗證

  • 所有 JSON 處理使用 System.Text.Json，未啟用多型反序列化（無 TypeNameHandling、無 JsonPolymorphic）。
  • 無 BinaryFormatter、無 XmlSerializer 直接吃使用者輸入的情境。
  • HTML 解析以 AngleSharp HTML5 parser 處理，不解析 DTD，無 XXE 風險。
  • 使用者輸入（關鍵字、設定）僅作為文字搜尋與設定儲存，未進入任何 SQL／Shell／反射執行路徑。

4.5 命令執行與子程序

  • 啟動爬蟲：ProcessStartInfo 結構化參數，UseShellExecute=false，引數來自 enum 與 DateOnly，無拼接字串注入空間。
  • 建立排程：呼叫 schtasks.exe，所有變數（scheduledTime 經 regex 驗證、crawlerExe 來自檔案系統查找）都不是使用者直接輸入。
  • 瀏覽器啟動：URL 經過 scheme 白名單（http／https only），阻擋 file://、javascript:、UNC 等被 ShellExecute 誤觸發。

4.6 供應鏈安全

  • MSI 透過 GitHub Actions 自動建置；建置流程公開於 .github/workflows/release.yml。
  • 套件來源限定 NuGet 官方 feed；無私有 feed、無 git 直接拉取。
  • 待補：MSI 數位簽章、SHA256 校驗、Dependabot 自動掃描（詳見第 7 節）。

05 弱點掃描結果

5.1 掃描方法

5.3 詳細發現

F-001

MSI 未數位簽章

High Pending
類別：供應鏈安全 ／ 位置：.github/workflows/release.yml、build/build-msi.ps1

建置流程沒有任何 signtool 或 Authenticode 步驟，產出的 MSI 與內含的兩支 EXE 均未簽章。Windows SmartScreen 將顯示「Unknown publisher」警告， 公司端 AppLocker／WDAC（Windows Defender Application Control）可能直接拒絕安裝。

建議：取得公司代碼簽章憑證後，在 CI 對 EXE 與 MSI 加 SHA-256 Authenticode 簽章。

F-002

排程任務以 SYSTEM 身份執行

High 已修
類別：權限提升 ／ 位置（修補前）：src/Tender.Installer/Product.wxs

原本 MSI 以 Impersonate="no"（SYSTEM）呼叫 schtasks /Create， 且未指定 /RU，導致建立的排程任務也以 SYSTEM 執行； 其 %LocalAppData% 解析至 systemprofile，桌面 app 完全看不到資料。

修補：移除 MSI Custom Action，改由桌面 app 首次啟動時建立使用者層級任務（/RL LIMITED）。

F-003

自動更新無檔案完整性驗證

Medium 已修
類別：供應鏈安全 ／ 位置：.github/workflows/release.yml

更新流程僅將使用者導向 GitHub Release 頁面下載，無 SHA256 比對、無簽章驗證。 若 GitHub Release 被篡改或維護者帳號被盜，使用者下載端無防禦。

修補：CI 在產 MSI 後自動以 Get-FileHash 計算 SHA256 並產出 TenderSearch.msi.sha256，隨 GitHub Release 一併公布。使用者下載後可自行 以 Get-FileHash 比對。最終的 Authenticode 簽章驗證仍需與 F-001 一併完成。

F-004

Excel 匯出未防 Formula Injection

Medium 已修
類別：注入攻擊 ／ 位置：src/Tender.Desktop/Services/ClosedXmlExcelExporter.cs

上游政府網站若出現以 =、+、-、@ 開頭的字串 （如 =HYPERLINK("https://evil","click")），匯出的 Excel 被使用者按 F2＋Enter 重新編輯時，可能被 Excel 解讀為公式並觸發。

修補：加入 SanitizeForExcel()，對所有自由文字欄位前置單引號（OWASP 建議）。

F-005

瀏覽器啟動未限制 URL scheme

Low–Medium 已修
類別：URL handler abuse ／ 位置：src/Tender.Desktop/Services/ProcessStartBrowserLauncher.cs、 src/Tender.Crawler/Parsing/AngleSharpTenderParser.cs

原本 Process.Start(url) UseShellExecute=true 未限制 scheme； 理論上若上游 HTML href 為 file://、javascript:、UNC 路徑等， 會交給 OS 預設 handler 執行。

修補：兩處皆加 scheme 白名單（http／https only），其他 scheme 直接忽略。

F-006

未自動掃描套件漏洞

Low 已修
類別：供應鏈監控 ／ 位置：.github/workflows/release.yml、 .github/workflows/ci.yml、.github/dependabot.yml

環境變數 用途 正式部署
TENDER_DATA_ROOT_OVERRIDE LocalAppDataPaths 用此值取代 %LocalAppData%/TenderSearch/data，給 UI 測試隔離臨時目錄用。 不設置；行為與 v1.6 一致（讀 bootstrap 檔 → fallback 預設 root）。
TENDER_TEST_MODE=1 啟用後 App.OnStartup 跳過 scheduled task install； ShellViewModel.LoadAsync 跳過 missed run / update check / cleanup； ShellWindow 上的兩顆 hidden test backdoor 按鈕（ TestModeOpenKeywordsManagerButton / TestModeOpenAppSettingsButton）變為 Visible 但 Margin 推到視窗外。 不設置；hidden 按鈕 Visibility=Collapsed 不在 visual tree。

這些 hook 不影響權限模型、不開外連、不寫 HKLM； env var 讀取為純字串比對 Environment.GetEnvironmentVariable。
